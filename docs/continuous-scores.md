# スタッフ向けSavantの比較指数と逆転目標

公開bundle生成時に検証済みの匿名実績から表示を生成する。Sheets、元の公開snapshotとmanifest、過去履歴、元データ照合は変更しない。採点方式は`reference-index-v3`。過去の実績も同方式で再計算し、旧方式の点数とは直接比較しない。

## 比較指数

点数を達成率・完成度と混同させないため、比較の基準を60、範囲を35〜85とする。定着・年度入会・成長・紹介は、対象実績の全チーム平均`m`からの差を換算する。実績を`x`、比較可能チームの範囲を`r`として、共通幅`w = r * 0.3 + m * 0.01`、指数`60 + 25 * (x - m) / hypot(x - m, w)`。上下限付近へ急に張り付けず、実績差と追い上げを連続的に反映する。最下位・最上位の点を固定しない。

同じ実績なら60。全員ゼロでも60（相対差なしであり、実績があることを示さない）。比較対象なし・未取得はnull。全チームを同倍率で変更しても指数は不変。指標内の実績と指数の大小は一致する。他チームの実績でも点数が動く。

- 定着：継続人数/対象人数。既存の対象20人以上、比較可能2チーム以上、期間重み1〜8を維持。
- 年度入会：年度の実体験→入会人数/実体験人数。前年率は説明用。
- 成長：大会上位30％加重点。
- 紹介：人数指数70％＋紹介率指数30％。紹介率は基準日の運用会員数を使用。
- イベント：従来の歴代MAX到達度を`35 + 到達度/2`へ換算。参加70％＋継続30％、一般会員対象のみ、発足前・大会限定練習・未開催の除外条件は維持。元の到達度と実参加率は書き換えない。

総合は丸め前の指数×既存配点30/20/20/15/15から計算し整数へ四捨五入。点数・点差・前回差分は整数。同じ表示総合なら同順位。画面と色の基準を60へ合わせ、「100点満点」とは表示しない。元の人数・率も併記する。

## 逆転目標

各チームから直上のチーム（同点の場合は同点相手）を対象とする。単独首位には首位と次のチームとの差を表示する。欠損により全体順位が確定できない場合は目標を保留する。

`overtake-targets.mjs`が匿名実績のコピーだけを変え、全チームの指数・総合・順位を同じ採点関数で再計算する。相手の実績を固定しても相手の相対点は変わるため、相手の点数を固定して引き算する計算は使わない。四捨五入後の自チーム総合が対象チームを厳密に上回る条件だけを表示し、同点を逆転と呼ばない。

- 逆転目標は今後の入会人数と紹介体験人数だけを変更する。継続率・大会・イベントの過去実績は固定する。
- 入会が増えた分だけ運用会員数と紹介率の分母も増やす。
- 紹介入会は入会人数の内数。紹介は新たに体験参加した人として年度体験人数と紹介ポイントに加算し、入会との二重計上を防ぐ。
- 紹介以外の入会は、現在の体験済み未入会人数を優先し、不足分は新規体験から全員入会した条件として年度体験人数にも加算する。実際の参加・入会を予測するものではない。
- 入会を`a`、紹介体験を`r`、現在の未入会体験者数を`u`とすると、新たな体験人数は`r + max(0, a - min(a,r) - u)`。会員数は`a`増、紹介ポイントは`r`増。紹介入会は`min(a,r)`人。

入会のみ、紹介体験のみ、既存体験者の入会を優先する方法、紹介入会を25/50/75/100％含む方法を各10000人まで探索する。実際に整数総合で上回る例から、追加人数が少ないものを1件表示する。全組み合わせに対する最適解・将来予測とは呼ばない。条件が出ない場合は無理な人数や過去実績の変更目標を表示しない。

カードには「入会あと○人（うち紹介入会○人）」などの人数と逆転相手だけを短く表示する。前提はカード外の「目標の試算条件」にまとめ、必要な人だけ展開する。

検証では表示条件を元の実績へ再適用し、同じ整数総合・相手総合と順位上昇を再現する。元データは変更しない。

`build-staff-pages.mjs`が毎朝の公開と表示変更の公開で共通使用される。元の7ファイルは維持し、投影後HTMLのSHA-256をbundleに付ける。ポータルのOIDC更新がbundleをD1/R2へ保存する。配信・保存ハッシュと公開画面を別々に確認する。
